# 扁平存储 Flat Storage

《深空当铺》（Probably Stolen）的全局仓储模组。在可平移、缩放的画布中展开容器的全部已解锁页面和机器控件，保留原有网格、物品占格及容量，支持跨容器、跨机器、跨页面拖放。

当前代码使用版本号 **1.3.2**，声明支持游戏兼容版本 `0.46D`，当前实测主菜单显示 `VERSION 100-Rev12`。支持视图平移、窗口刷新、指针检测和小地图更新的性能采集。游戏内回归项目见 [验证清单](GAMEPLAY_CHECKLIST.md)。

## 安装与打开

将发布包中的 `ProbablyStolen_FlatStorage` 文件夹放入游戏的 `Mods` 目录。在游戏模组管理界面启用 `Flat Storage`，加载存档后按反斜杠键 `\`，或点击画面右上角的“扁平存储”。

在游戏选项的“扁平存储”分区修改快捷键和以下配置。配置使用游戏提供的 `ModConfig` 保存。

| 配置 | 默认值 | 范围与作用 |
| --- | --- | --- |
| 新场景默认缩放 | 100% | 25%～200%；首次创建该场景布局时使用 |
| 仓储刷新间隔 | 0.25 秒 | 0.10～2.00 秒；控制仓储发现与结构检查频率 |
| 边缘平移速度 | 12 | 0～30；数值越大速度越快，0 关闭边缘自动平移 |
| 新场景自动排列 | 开启 | 开启或关闭；首次创建该场景布局时使用 |

已有场景继续使用存档中的缩放和自动排列状态。新场景首次打开时保留配置的缩放，并将视口移到柜台或首个可访问分组。

界面文字提供简体中文和英文资源，跟随游戏语言。类别名称使用游戏提供的本地化名称。

## 操作

| 操作 | 输入 |
| --- | --- |
| 打开或关闭画布 | 反斜杠键 `\`，可配置 |
| 围绕指针缩放 | 鼠标滚轮，范围 25%～200% |
| 平移画布 | 在空白处按住右键拖动，或使用中键、空格加左键拖动 |
| 移动容器或机器分组 | 关闭“自动排列”后，左键拖动分组标题 |
| 切换自动排列 | 点击底部“自动排列 开 / 关”，默认开启 |
| 转移物品 | 左键拖动到目标网格 |
| 框选多个物品 | 在画布或网格空白处按住左键拖出选区，再拖动已选物品 |
| 打开店内交易页面 | 点击底部“交易页面” |
| 查找物品 | 在底部输入名称、标识符或类别名称，并按需选择类别 |
| 聚焦下一件匹配物品 | 在搜索框按 `Enter`，或点击“下一个” |
| 查看容器目录 | 点击底部“容器目录” |
| 预览自动收纳 | 点击底部“自动收纳”，检查匹配容器和数量后确认 |
| 显示或隐藏小地图 | 点击底部“小地图”，开关随当前场景保存 |
| 记录操作与性能 | 点击底部“性能分析”，选择“开始记录” |
| 拖动物品时调整原生数量 | `Ctrl` 加滚轮，遵循游戏原有数量修饰键规则 |
| 取消框选、选择或物品拖动 | `Esc` |
| 关闭画布 | 空闲时按 `Esc`，或点击“关闭” |

拖动物品接近画布边缘时，画布自动平移。物品旋转、翻转、拆分和右键菜单沿用游戏设置。页面底部的操作栏提供“适应全部”“100%”“重新排列”“交易页面”“自动排列”和“关闭”。

“交易页面”会取消当前拖动、保存画布布局，并在画布上方打开游戏原有交易面板。仓储画布保持打开，交易窗口中的点击和滚轮交给原生控件处理。交易面板打开时，`Esc` 优先交给游戏处理该面板。该入口用于店内柜台交易；顾客、价格、报价及交易条件均由游戏处理。

## 搜索与导航

搜索范围为当前画布中可访问页面的物品。输入内容可以匹配物品名称、`identifier`、类别标识或本地化类别名称；文字匹配忽略大小写及查询两端空格。类别下拉选项与文字查询共同筛选结果。

启用搜索或类别筛选后，匹配物品显示高亮边框，其余物品变暗。点击“清除”恢复显示。按 `Enter` 或点击“下一个”循环聚焦匹配物品；滚动库存会同步滚动到对应物品。

搜索、类别筛选、目录、收纳和画布操作集中在底部工具栏。工具栏使用统一的深色配色、控件高度和间距，按窗口宽度换行；类别菜单向上展开，列表高度固定并支持滚动。

“容器目录”按照实际所属关系显示树形目录。点击名称左侧的箭头展开或折叠子容器，点击名称定位对应分组。名称显示当前容器的标签或名称，悬停显示所属标签；同级名称按固定顺序排列。容器移动、增加、移除或修改名称后，目录更新对应层级，并保留有效的折叠状态与滚动位置。深层目录支持横向滚动。

小地图常驻画布右下角，通过底部“小地图”按钮切换显示，开关随存档和场景保存。点击地图中的分组聚焦对应容器；点击地图空白位置移动视口。小地图显示全部分组位置和当前视口范围。

## 自动收纳

点击底部“自动收纳”，模组为主柜子、窗内桌面和窗外桌面上的自有散放物品寻找普通容器。容器需要已打开且可访问，内部已有物品用于确定收纳类别。容器本体、机器和固定设施保持原位。顾客在场时，两张桌面上的物品及其中的容器保持原状，主柜子仍可参与收纳。

匹配向量包含用途类别、违禁属性与等级、被盗状态、危险废物状态及物品属性。容器向量根据直接存放物品的实际占格加权，按余弦相似度排序。候选容器必须存在用途类别交集；空容器和没有匹配类别的物品保留原状。最佳匹配容器容量不足时，继续尝试其余匹配容器。

收纳预览显示每件物品的目标容器、数量、匹配度和保留原因。点击“确认转移”后，模组按计划逐件调用游戏原生接口，检查所有权、固定、锁定、嵌套、占格及数量限制。

确认前会重新检查存档、场景、顾客、可访问页面及源、目标物品状态。状态变化时需要重新预览。执行过程中每件物品都会再次接受检查；转移条件变化时立即停止，已经完成的转移保留，其余物品留在原位，并显示已完成数量和停止原因。

## 仓储与机器

画布按照当前场景收集可访问仓储。箱子、背包和嵌套容器需要先在原有界面打开，随后才会加入画布；上锁容器需要先完成解锁。嵌套内容沿着满足访问条件的容器逐层展开。水龙头使用游戏原有解锁条件。

剧情容器使用游戏的 `TRACK_OPENED_TAG` 与 `OPENED_TAG` 判定打开状态。普通容器使用原有窗口的真实打开记录；已有存档通过原生窗口位置记录识别曾经打开的容器。历史记录不足的容器，在原有界面打开一次后加入画布。

同一对象的页面横向展开，机器控件直接调用原有操作回调。物品转移使用真实 `GameInventory` 和 `SlotMarker`，由游戏检查占位、容量、类型、所有权和机器限制。

容器标题显示“父容器标签 / 自身标签”，空标签使用名称。分页标题显示所属容器标签与页面标签。分组宽高由原生窗口像素尺寸决定，过长的标题显示省略号。

分组位置、视口位置和缩放随存档保存，并按场景分别记录。切换场景前保存当前场景布局；读取其他存档时按存档身份隔离布局。读档时清理已经不存在物品的打开记录与分组位置，并保留其他场景中仍然存在的物品记录。

## 自动排列

自动排列默认开启，开关状态按存档和场景保存。开启时禁止手动拖动分组标题，画布平移、缩放及物品拖放照常使用。首次生成布局、打开自动排列模式或点击“重新排列”时，模组按当前屏幕宽高比计算紧密排列。

- 窗内外桌面组成中心区域，主柜子放在桌面下方。
- 容器沿中心区域外围排列，嵌套容器放在其父容器更靠外的位置，并优先靠近父容器。
- 同类机器优先相邻。容器内容使用物品类型及实际占格比例计算余弦相似度；相同和相近标签提供辅助权重。空容器按类型与标签归类。
- 每个容器的全部页面作为一个完整分组参与排列，页面顺序和尺寸保持原值。分组之间保留 16 个画布单位的间距。
- 算法比较三种放置顺序，尝试矩形边缘的候选位置，并对最多 96 个分组执行局部位置优化。评分同时考虑屏幕比例、整体面积、父子距离和相似内容的邻近程度。

这是带布局约束的启发式优化，数学上的全局最密解没有保证。宽大的多页面分组会影响最终外形与屏幕比例的接近程度。相似度使用各分组直接存放的物品，嵌套容器的内容在自己的分组中计算。

自动排列开启时，可展示容器增减、容器归属变化，以及分页尺寸和屏幕尺寸变化，会触发重新排列。拖动或平移期间的变化会延后合并处理，结束后执行。自动更新保留当前平移和缩放，点击“适应全部”可以查看完整布局。

普通内容变化、数量变化、标签变化，以及容器在同一网格中移动时，已有分组位置保持稳定。点击“重新排列”会按照当前内容和标签重新计算相似度与位置。

关闭自动排列后，可以手动拖动标题；新增分组加入现有内容外侧，已有位置随存档保存。再次开启时立即按当前场景排列。

机器生产、物品消耗与页面变化通过原生库存回调和页面事件更新相关窗口。窗口结构、布局和物品目录分别记录变化，重复通知合并处理。画布按配置的刷新间隔分散检查窗口内容，仓储发现采用分帧扫描，周期至少为 1 秒。

窗口使用独立 Canvas 和空间索引。视口外窗口关闭对应的 Canvas 与 GraphicRaycaster，附近窗口提前准备布局，进入和退出采用不同的边界范围。平移与缩放复用小地图投影及分组标记，仅更新视口边框；指针查询按帧、坐标和界面状态缓存。拖动预览及原生落点校验保持同步，游戏时间遵循现有游戏规则。

仓储 Canvas 关闭像素取整，平移时复用已有图形几何数据。指针检测先检查容器边界，再调用原生图形检测；整个视口使用 stencil 裁剪，容器内部保留游戏原有裁剪规则。

## 性能分析与导出

打开底部工具栏的“性能分析”，使用“逐帧统计”模式点击“开始记录”。在原有场景完成静止、平移、缩放和物品拖动等操作，点击“停止”后自动导出。“标记”会按顺序记录编号，便于在报告中找到当时的操作。“收起”保留录制控件和统计；关闭面板后继续采样，再次点击“性能分析”可查看录制状态。

针对移动视图时的卡顿，可以静止 5 秒，连续平移约 15 秒，再静止 5 秒。保持相同缩放和容器内容，分别采集容器较少、容器较多的视图。复现瞬间可以添加标记。采样会记录实际视图位置、缩放、鼠标坐标、按键、可见容器数量、物品数量、UI 图形数量和待刷新数量。

面板显示逐帧耗时曲线、中位数、P95、P99 和最长帧。点击曲线、使用“上一帧”“下一帧”或“最长帧”查看对应帧；“实时”恢复跟随最新帧。详情可切换函数耗时、引擎指标和操作事件。正在记录时，统计覆盖最近 300 个已完成帧；停止后统计覆盖全部完整帧。

| 模式 | 采集内容 |
| --- | --- |
| 逐帧统计 | 每帧记录全部已挂接函数的调用次数、包含子调用耗时、自身耗时和最长单次耗时；额外保留达到 0.25 ms 的调用明细 |
| 详细调用 | 保留每次已挂接函数调用的开始时间、持续时间、嵌套层级和容器身份，适合采集短时间复现过程 |
| 帧时间基准 | 记录帧间隔、操作、数量与引擎计数器，用于衡量函数和阶段计时的额外开销 |

逐帧统计和详细调用覆盖 36 个托管入口，包括输入分发、模组更新、仓储发现、窗口同步、视图应用、搜索、小地图、指针检测、裁剪、图形几何更新、材质更新、文字生成及窗口、网格和物品验证。同时记录 Unity 的矩形更新、Canvas 更新、几何提交、渲染完成和画面提交阶段。采样在录制期间启用，停止后移除。

每次最多记录 60,000 帧、200,000 条调用明细和 16,000 条事件。达到任一上限时，在当前帧完成后停止并导出；该帧超出容量的明细数量写入报告。切换场景、读取存档、禁用模组或正常退出游戏时，也会结束录制并导出。进程被强制终止时，内存中的录制数据可能丢失。

导出目录为游戏的 `Application.persistentDataPath/FlatStorage/Performance`。Windows 默认位置为：

```text
%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\FlatStorage\Performance
```

点击“复制路径”可以复制导出目录。每次导出生成一个 ZIP 文件和同名 HTML 报告。用浏览器打开 HTML，即可离线筛选操作和帧区间、查看峰值对应的调用，并下载原始 JSON。交付分析时提供完整 ZIP 文件。

报告的“视图实际平移”和“视图实际缩放”根据相邻帧的视图坐标判定；“视图连续静止”要求连续三个采样帧保持位置和缩放。按住鼠标期间的全部帧归入“平移操作期间”。报告同时保存模组文件 SHA-256、Canvas 像素设置和图形所属容器，便于比较不同构建与相同场景。

| ZIP 内文件 | 内容 |
| --- | --- |
| `capture.json` | 完整帧、调用明细、操作事件、计数器、原始时间戳、字段定义、硬件信息、模组列表与计量定义 |
| `frames.csv` | 每帧耗时、输入状态、视图状态与 UI 数量 |
| `metrics.csv` | 每帧各函数的调用次数和耗时统计；函数编号对应 JSON 中的 `metricNames` |
| `report.html` | 内嵌全部数据的离线交互报告 |
| `trace.json` | Chrome Trace Event 格式的调用时间线、帧计数器和事件 |

导出使用后台任务执行序列化、压缩和文件写入。采样错误或导出错误会显示在面板详情并写入游戏日志。导出失败时保留当前记录；处理文件权限或磁盘空间问题后，点击“导出”重试。成功导出后可以开始下一次录制。

### 指标含义

- 帧间隔：连续两次记录器 `Update` 采样边界之间的单调时钟间隔，包含游戏工作、渲染等待和帧率限制产生的等待。正常停止会等待当前帧完成；退出过程中的部分帧单独标记，并从百分位统计中排除。
- 函数耗时：使用 `Stopwatch` 记录主线程调用。包含子调用的耗时存在重叠；自身耗时扣除直接嵌套的已挂接调用。原始时钟计数作为十进制文本保存，避免浏览器数值精度损失。
- Unity 阶段：`NativeCanvasUpdate` 包含 `PlayerUpdateCanvases` 内的原生工作及其回调；`CanvasUpdate` 与 `CanvasRender` 是其中的托管入口。阶段与子调用的总耗时存在重叠。`NativeCanvasTransform` 对应采样区间结束前的 `EarlyUpdate.UpdateCanvasRectTransform`；其余原生阶段位于 `PostLateUpdate`。
- 引擎计数器：记录当前游戏运行时实际提供的 CPU、渲染、GPU、内存、GC 和绘制指标。缺失样本导出为 `null`，界面显示“不可用 / 本帧无样本”。
- 原始帧计时：保留引擎返回的 CPU/GPU 耗时、原始时间戳和观察帧。数据可能延迟返回，来源 Unity 帧编号未知，因此独立展示。
- 操作与数量：输入状态在 `LateUpdate` 采样，平移还包含实际视图位置变化。容器图形与物品数量每 0.5 秒采样，数据中保留数量采样时的帧编号。`Panel` 标志表示指针位于分析面板内，`panelVisible` 表示面板显示状态。
- 采集开销：`Recorder` 和 `Panel` 分别记录采集器与面板更新耗时，函数挂接自身仍有额外开销。使用相同场景和操作路径分别采集“帧时间基准”与“逐帧统计”，可以比较计时开销。开始录制会分配固定容量缓冲区，正式逐帧采样从下一次 `Update` 开始。

## 构建与游戏外验证

需要 .NET SDK 10，以及本地游戏 `Probably Stolen_Data/Managed` 中的程序集。模组目标为 `netstandard2.1`。接口检查针对本地兼容版本 `0.46D`（主菜单 `VERSION 100-Rev12`）程序集执行。`manifest.xml` 的 `GameVersions` 使用 `Application.version`，其值来自游戏资源 `PlayerSettings.bundleVersion`。

在项目目录运行：

```powershell
dotnet build -c Release -p:SkipInstall=true
dotnet run --project Tests/FlatStorage.Tests.csproj -- .
```

需要将构建产物安装到本地游戏时执行：

```powershell
dotnet build -c Release
```

构建产物位于 `bin/Release/netstandard2.1`，默认安装目录为游戏的 `Mods/ProbablyStolen_FlatStorage`。可以通过 MSBuild 属性 `ModInstallDir` 指定发布目录。

从 GitHub 克隆到其他位置时，可以显式指定本地游戏目录与程序集目录：

```powershell
dotnet build -c Release -p:SkipInstall=true '-p:GameDir=D:\Games\Probably Stolen'
dotnet run --project Tests/FlatStorage.Tests.csproj '-p:ManagedDir=D:\Games\Probably Stolen\Probably Stolen_Data\Managed' -- . 'D:\Games\Probably Stolen\Probably Stolen_Data\Managed'
```

## 打包与发布

发布工具需要 PowerShell 7、.NET SDK 10、Python 3 和本地游戏程序集。Python 依赖版本固定在 `scripts/requirements-release.txt`，安装到项目内的 `.work/release-python` 环境。实际上传时需要 SteamCMD。

在项目目录生成并核验发布包：

```powershell
.\Publish.cmd -ValidateOnly
```

该命令构建独立发布目录、运行游戏外测试，核对程序集版本、资源文件、双语 CSV、预览图、Workshop VDF 和压缩包内容。安装包输出为 `dist/FlatStorage-1.3.2.zip`，上传目录与生成的 `upload.vdf` 位于 `.work/releases/`。发布包保留 `Localization/zh.csv` 和 `Localization/en.csv` 的目录结构。

可以直接调用 PowerShell 脚本并指定游戏目录：

```powershell
pwsh -NoProfile -File .\scripts\Publish-Workshop.ps1 -ValidateOnly -GameDir 'D:\Games\Probably Stolen'
```

`preview.png` 是预览图源文件，`Workshop/description.zh.txt` 和 `Workshop/description.en.txt` 保存完整中英文说明，`Workshop/upload.vdf` 保存目标条目配置。每个发布版本在 `Workshop/changelogs/<version>.txt` 中维护更新日志，打包时写入上传配置。打包工具生成用于上传的 JPEG 预览图。常规发布保留创意工坊现有标题与说明；明确更新说明时，分别维护简体中文和英语页面，每份文案的 UTF-8 长度需小于 8000 字节。

完成游戏内验收后，运行 `.\Publish.cmd` 进入上传流程。脚本会再次构建和验证发布包，显示公开的 Workshop 条目 `3833606510` 与应用 `4348910`，并要求手动输入 `PUBLISH`。随后输入 Steam 账户名，在 SteamCMD 中完成密码与 Steam Guard 验证。上传完成后核对 SteamCMD 结果和创意工坊页面。

## 运行错误

接口缺失或布局数据无效时，模组立即报告错误。画布操作异常时停止当前操作、关闭画布、释放接管的窗口，并显示错误信息；入口保留，可以重新尝试打开。交易界面尚未就绪时显示提示并记录日志。模组统一通过 `ModLog` 记录异常详情。

反馈问题时提供游戏版本、涉及的容器或机器名称、操作步骤和对应日志。布局数据保存在游戏存档的 `flat_storage` 模组数据中，使用 `layout:<场景>` 键；容器打开记录使用 `opened:<物品身份>` 键。快捷键和四项配置由游戏的模组配置系统管理。
