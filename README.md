# 扁平存储 Flat Storage

《深空当铺》（Probably Stolen）的全局仓储模组。在可平移、缩放的画布中展开容器的全部已解锁页面和机器控件，保留原有网格、物品占格及容量，支持跨容器、跨机器、跨页面拖放。

当前版本为 **1.1.0**，使用 C#、Unity 和 Harmony，接口检查基于游戏 `VERSION 100-Rev6`。运行结果与游戏内待验证项目见 [验证清单](GAMEPLAY_CHECKLIST.md)。

## 安装与打开

将发布包中的 `ProbablyStolen_FlatStorage` 文件夹放入游戏的 `Mods` 目录。在游戏模组管理界面启用 `Flat Storage`，加载存档后按反斜杠键 `\`，或点击画面右上角的“扁平存储”。

在游戏选项的“扁平存储”分区修改快捷键。快捷键配置使用游戏提供的 `ModConfig` 保存。

## 操作

| 操作 | 输入 |
| --- | --- |
| 打开或关闭画布 | 反斜杠键 `\`，可配置 |
| 围绕指针缩放 | 鼠标滚轮，范围 25%～200% |
| 平移画布 | 在空白处按住右键拖动，或使用中键、空格加左键拖动 |
| 移动容器或机器分组 | 左键拖动分组标题 |
| 转移物品 | 左键拖动到目标网格 |
| 打开店内交易页面 | 点击底部“交易页面” |
| 拖动物品时调整原生数量 | `Ctrl` 加滚轮，遵循游戏原有数量修饰键规则 |
| 取消物品拖动 | `Esc` |
| 关闭画布 | 空闲时按 `Esc`，或点击“关闭” |

拖动物品接近画布边缘时，画布自动平移。物品旋转、翻转、拆分和右键菜单沿用游戏设置。页面底部的操作栏提供“适应全部”“100%”“重新排列”“交易页面”和“关闭”。

“交易页面”会取消当前拖动、保存画布布局并归还原生窗口，然后打开游戏原有交易面板。按反斜杠键 `\` 可以重新进入仓储画布。该入口用于店内柜台交易；顾客、价格、报价及交易条件均由游戏处理。

## 仓储与机器

画布按照当前场景收集可访问仓储。箱子、背包和嵌套容器需要先在原有界面打开，随后才会加入画布；上锁容器需要先完成解锁。嵌套内容沿着满足访问条件的容器逐层展开。水龙头使用游戏原有解锁条件。

剧情容器使用游戏的 `TRACK_OPENED_TAG` 与 `OPENED_TAG` 判定打开状态。普通容器使用原有窗口的真实打开记录；已有存档通过原生窗口位置记录识别曾经打开的容器。历史记录不足的容器，在原有界面打开一次后加入画布。

同一对象的页面横向展开，机器控件直接调用原有操作回调。物品转移使用真实 `GameInventory` 和 `SlotMarker`，由游戏检查占位、容量、类型、所有权和机器限制。

容器标题显示“父容器标签 / 自身标签”，空标签使用名称。分页标题显示所属容器标签与页面标签。分组位置、视口位置和缩放随存档保存，并按场景分别记录。

## 自动排列

首次生成布局或点击“重新排列”时，模组按当前屏幕宽高比计算紧密排列。

- 窗内外桌面组成中心区域，主柜子放在桌面下方。
- 容器沿中心区域外围排列，嵌套容器放在其父容器更靠外的位置，并优先靠近父容器。
- 同类机器优先相邻。容器内容使用物品类型及实际占格比例计算余弦相似度；相同和相近标签提供辅助权重。空容器按类型与标签归类。
- 每个容器的全部页面作为一个完整分组参与排列，页面顺序和尺寸保持原值。分组之间保留 16 个画布单位的间距。
- 算法比较三种放置顺序，尝试矩形边缘的候选位置，并对最多 96 个分组执行局部位置优化。评分同时考虑屏幕比例、整体面积、父子距离和相似内容的邻近程度。

这是带布局约束的启发式优化，数学上的全局最密解没有保证。宽大的多页面分组会影响最终外形与屏幕比例的接近程度。相似度使用各分组直接存放的物品，嵌套容器的内容在自己的分组中计算。

日常取放和机器生产保持分组位置稳定。新增分组加入现有内容外侧。已有存档继续使用保存的位置，点击“重新排列”即可应用当前规则；手动移动后的布局会继续保存。

机器生产、物品消耗与页面变化同步到原生控件。画布每 0.25 秒检查仓储分组和页面结构变化；视口外的分组关闭渲染与指针命中。游戏时间遵循现有游戏规则。

## 构建与游戏外验证

需要 .NET SDK 10，以及本地游戏 `Probably Stolen_Data/Managed` 中的程序集。模组目标为 `netstandard2.1`。接口检查针对本地 `VERSION 100-Rev6` 程序集执行。

在项目目录运行：

```powershell
dotnet build -c Release -p:SkipInstall=true
dotnet run --project Tests/FlatStorage.Tests.csproj -- .
```

执行默认安装构建：

```powershell
dotnet build -c Release
```

构建产物位于 `bin/Release/netstandard2.1`，默认安装目录为游戏的 `Mods/ProbablyStolen_FlatStorage`。可以通过 MSBuild 属性 `ModInstallDir` 指定发布目录。

从 GitHub 克隆到其他位置时，可以显式指定本地游戏目录与程序集目录：

```powershell
dotnet build -c Release -p:SkipInstall=true '-p:GameDir=D:\Games\Probably Stolen'
dotnet run --project Tests/FlatStorage.Tests.csproj '-p:ManagedDir=D:\Games\Probably Stolen\Probably Stolen_Data\Managed' -- . 'D:\Games\Probably Stolen\Probably Stolen_Data\Managed'
```

生成可安装目录：

```powershell
dotnet build -c Release -p:ModInstallDir=dist/ProbablyStolen_FlatStorage
Compress-Archive -Path dist/ProbablyStolen_FlatStorage -DestinationPath dist/FlatStorage-1.1.0.zip -Force
```

游戏外验证覆盖缩放锚点、缩放限制、分组排列、视口交集、布局文件读写、损坏数据拒绝、程序集引用、Harmony 目标与参数，以及游戏自带 `ModScanner` 对 DLL 的实际扫描。

Release 编译和 20 项游戏外验证已通过。排列验证覆盖内容相似度、柜台中心、嵌套方向、间距、确定性、四种屏幕比例和 120 个分组的排列。转移变换测试使用实际交接策略与仿射矩阵，在 25%、50%、75%、100%、150%、200% 缩放下分别执行 100 次交接，检查尺寸及物品局部坐标的映射。游戏内交互验证由使用者执行，具体项目见 `GAMEPLAY_CHECKLIST.md`。

程序集检查覆盖 23 个 Harmony 目标。文字渲染、拖动期间的预览保护、放下后的贴图与网格一致性，以及连续跨容器移动，需要通过清单中的游戏内步骤确认。游戏外测试覆盖独立逻辑与程序集接口，Unity 渲染和指针交互的结果以游戏内验证为准。

## 运行错误

接口缺失或布局数据无效时，模组立即报告错误。画布运行异常时释放接管的窗口，停止该画布实例，并显示错误信息。游戏日志包含异常详情。

反馈问题时提供游戏版本、涉及的容器或机器名称、操作步骤和对应日志。布局数据保存在游戏存档的 `modData` 中，键以 `flat_storage` 为前缀；快捷键由游戏的模组配置系统管理。
