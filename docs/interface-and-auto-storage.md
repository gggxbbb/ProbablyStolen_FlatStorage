# 画布界面与自动收纳

## 界面

画布使用深灰背景、统一控件尺寸和绿色强调色。搜索、类别、下一个、清除、容器目录、自动收纳和小地图开关组成底部第一组；适应全部、100%、重新排列、交易页面、自动排列和关闭组成第二组。工具栏按可用宽度换行，常见宽度采用两行。类别菜单向上展开，固定行高和滚动区域限制列表尺寸。

小地图位于画布右下角、工具栏上方，显示全部分组及当前视口。点击分组定位容器，点击空白位置移动视口。底部按钮控制地图显示，`CanvasState.ShowMiniMap` 按存档和场景保存，已有布局默认显示地图。地图覆盖区域独立处理点击，画布平移、缩放和物品目标选择遵循最上方界面的命中结果。

## 来源与目标

来源为店内 `invElement`、`frontInvinvElement`、`backInvinvElement` 的直接自有散放物品。容器本体、机器与固定设施保持原位；具有改装窗口的普通枪械和工具可以参与收纳。

目标为当前画布中已打开、已解锁、归玩家所有的普通容器，包括箱子、背包、袋子、保险柜和普通多页仓储。类别与标签用于判定容器，窗口外观不决定资格。目标容器的直接内容形成分类依据；嵌套容器独立参与匹配。

顾客在场时保护两张桌面的物品及其内部容器，主柜子仍可参与收纳。预览列出被保护的物品及原因。

## 匹配规则

每件物品使用游戏提供的用途类别、违禁状态与等级、被盗状态、危险废物状态及品质等属性构造向量。用途类别归一化到总长度 1，违禁状态权重为 0.5，违禁等级、来源、危险属性和每项附加属性的权重为 0.25；最终向量进行单位归一化。

容器内容按实际占格加权求和后归一化。候选容器须与物品存在用途类别交集，随后按余弦相似度降序排列。同分时按容器持久化标识排序，以保持结果稳定。空容器和没有用途类别交集的物品保持原状。

一次预览使用固定的容器内容向量。每个目标页面共用容量与占格预留，最佳匹配容量不足时继续尝试下一匹配容器。物品和容器使用确定的遍历顺序，预览时所有库存保持原状。

## 确认与执行

预览显示目标容器、数量、匹配度与保留原因。确认时复核存档、场景、顾客上下文、库存结构、物品身份、数量、形状、相关状态及报价特征，并重新计算转移步骤。机器保留身份、数量和占格检查，其运行进度可以继续变化。

转移逐件调用游戏原生权限、合并、占格和插入接口。每次执行继续检查当前来源、目标及原生许可。条件变化时终止后续转移，已完成部分保留，结果显示已完成数量和停止原因。

## 验证范围

游戏外测试覆盖向量类别交集、各类属性、占格加权、排序稳定性、无匹配输入、工具栏连续宽度布局、小地图坐标映射及显示状态保存。真实游戏程序集用于形状预留、报价特征、接口与 ModScanner 检查。游戏内外观与完整交互由使用者按 [验证清单](../GAMEPLAY_CHECKLIST.md) 验收，Workshop 发布安排在验收完成之后。
